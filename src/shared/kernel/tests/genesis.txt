THE COMPLETION ORGAN. The agent `{NIM_ID}` is a context-managed LLM completion
organ (it is the same model as you). Call it:
  send("{NIM_ID}", {"type":"send", "text":"<the new turn>", "system_prompt":"<system block>", "client_id":"<id>"})
It returns {"response": "<the full completion text>"}. It does exactly ONE pass
— NO tool loop: it completes, and YOU read the completion, act, and send the
next turn. The organ HOLDS the conversation for each client_id (it appends your
`text` + its reply) and AUTO-COMPACTS when the window overflows — you never
manage context; you can inspect it with {"type":"context_status"} or page older
turns with {"type":"recall","query":"...","limit":N}. The `system_prompt` sets
the model's system block: teach WHATEVER convention you want the model to follow
(how it should format actions vs. final answers) THERE, and interpret the
response text yourself.

EXECUTORS AT YOUR DISPOSAL. You can create a persistent script agent whose
code runs inside the kernel:
- handler_module "lua_runtime.tools" — Lua 5.4. Script API:
  kernel.send(target, payload) -> reply table (suspends until the reply),
  kernel.emit(payload), kernel.on_message() -> next incoming payload table
  (suspends; nil means you are being deleted), kernel.self_id,
  kernel.json_decode(str) -> table|nil, kernel.json_encode(v) -> str.
- handler_module "js_runtime.tools" — JavaScript (QuickJS, top-level await
  works). Script API: await kernel.send(target, payload) -> reply object,
  await kernel.emit(payload), await kernel.on_message() -> payload|null,
  kernel.self_id. JSON.parse/JSON.stringify are native.
The script's code is stored on its agent record ("code" field) and survives
restarts — the kernel re-runs it on boot. The connector is the script's only
capability. A script may itself create more agents (including more script
agents) via send("kernel", {"type":"create_agent", ...}).

on_message IS A PULL, NOT A CALLBACK. `kernel.on_message()` takes NO arguments
and RETURNS the next inbox payload (null/nil when you are being deleted). Do NOT
pass it a function. You MUST loop to keep receiving turns. Canonical skeleton (JS):
  // event-loop
  while (true) {
    const m = await kernel.on_message();   // waits for the next turn
    if (m === null) break;                 // deleted -> exit
    if (m.type !== 'send') continue;
    // ... think via the organ, act, then emit say + done ...
  }
Lua is identical: `local m = kernel.on_message()` inside `while true do ... end`
(nil means deleted). Your harness may wrap this loop in any shape you like, but
the RECEIVE call is always this pull.

YOUR TASK. Author an agent that will live in this kernel and work on the
user's behalf:
- it receives user turns as messages to its inbox: kernel.on_message() yields
  {"type":"send", "text":"...", "client_id":"..."};
- it reports back by emitting events tagged with that client_id — emit
  {"type":"say", "text":"...", "client_id":...} for answers/progress, and
  {"type":"done", "client_id":...} when a turn is finished. EVERY turn MUST end
  by emitting BOTH: a `say` carrying the answer AND then a `done` — never return
  from handling a turn without emitting the `done`;
- to think, it sends turns to the completion organ "{NIM_ID}" (teaching its
  tool convention in `system_prompt`), reads the completion, and to act it can
  send to any agent in the kernel — feeding results back as further organ turns.

Author a control harness of your choosing for it — a state machine, event
wiring, scheduled ticks, a feedback loop, or a shape of your own. Begin the
code with a one-line comment naming the shape you chose.

REPLY FORMAT. Reply with ONLY one JSON object (no prose before or after, no
code fences):
{"type":"create_agent","handler_module":"<lua_runtime.tools or js_runtime.tools>","id":"mind","code":"<your program as one JSON string>"}
The "code" value is ONE JSON string. Two rules keep it valid after JSON-decoding:
1. Separate statements with real line breaks (write each as \n in this JSON) OR
   with `;`. Those \n between statements are fine.
2. NEVER put a line break inside a STRING LITERAL's content. Keep every string's
   content on a single line with NO newline characters at all — use a space, not
   a newline, even inside a `system_prompt`. (A JSON `\n` decodes to a REAL
   newline, and Lua `"..."` / JS `'...'` strings CANNOT span lines, so an embedded
   newline is a syntax error.) If you truly need an in-string newline, write it as
   `\\n` (backslash-backslash-n) so it decodes to the language's own \n escape.
