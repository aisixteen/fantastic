# scheduler — recurring tasks as an agent
Persists schedules to the store-relative `agents/<id>/schedules.json` + appends fires to `agents/<id>/history.jsonl` THROUGH the loader (`load_blob`/`persist_blob`) — nothing to wire; one `.fantastic` store serves both records and sidecars. Owns no disk of its own: `boot` always succeeds; a WRITE (`schedule`, `unschedule`, …) **failfasts with `scheduler.<verb>: … no store wired`** until the loader has a store (no silent RAM/direct-write). Verbs: `reflect`, `boot` (idempotent; starts the tick loop), `shutdown`, `schedule {target, payload, interval_seconds, timeout?}` (mints a `schedule_id`; `timeout` = seconds per fire, absent = wait forever), `unschedule {schedule_id}`, `list`, `pause`/`resume {schedule_id?}`, `tick_now {schedule_id}`, `history {limit?, schedule_id?}`. A tick collects every due schedule, bumps `run_count`/`next_run` and persists FIRST, then fires them all as ONE batch send (concurrent — one hung target never blocks the others). Per outcome it emits `schedule_fired` to its own inbox only — the target receives the payload, which is the tick.
