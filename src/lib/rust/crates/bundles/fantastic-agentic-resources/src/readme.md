# agentic_resources — a registry of agent roles
Verbs: reflect, roles, role, spawn, report, fleet, set_limit, get_count. **Off by default**: a host registers this bundle only when `FANTASTIC_AGENTIC_RESOURCES` is truthy, and an agent of it with no `role_dirs` in its record refuses every verb (`agentic_resources is disabled`).

**Config is the record.** `role_dirs` (folders of role cards), `tiers` (`{tier: backend fields}`; a card names a tier KEY, never a model), `limits` (kept by `set_limit`). A role is any kind of agent, not only code.

**A role card** is one `*.md` file: a `---` header (`name`, `purpose`, `tier`, `grants`) then the directive text, which becomes the child's system prompt. `grants` is the child's `can_call`; the key `$registry` stands for this registry. Adding a file adds a role (cards are re-read on every call); a bad card is listed in `roles` `errors` and skipped. A generic `project_lead` card ships built in.

**`spawn {role, task?, name?, limits?}`** makes the agent as a CHILD OF THE CALLER and gives the caller `pause`, `resume` and `stop` on it (both ends of the grant), so a lead always controls its subtree. A `task` string is sent to the child as its first message (any other `task` is `bad_arg`). The child tells its parent with `report {state, result}`: the parent gets a `{type:"report", from, state, result}` message and nothing is stored on any record. The task tree is `task_registry`'s, not this registry's.

**`spawn {role, from:{agent, at}, task?, name?, limits?}`** branches the new agent off a fork point of an existing agent (`fork_points`, `mark`): the registry asks ai_core to `fork {at}` that agent, then applies the role card (directive, tier, grants) and the limits like any spawn. The fork stays in the source's memory store (so its copied prefix is readable and the prompt cache is warm; a tier with another model starts cold), keeps the store grant and none of the source's other grants, and its `limits`, `role` and `spawned_by` are the new spawn's, never the source's (a `task` on the source record is dropped). Placement: the fork lands BESIDE its source (under the source's parent), not under the caller; the caller still gets `pause`, `resume` and `stop` on it. The caller must itself hold `fork` on `agent`, or the spawn is refused `not_allowed`. The registry's limits are checked before anything is forked, and a refusal from fork (`no_such_row`, `cuts_turn`, `cuts_fold`, `parent_mid_turn`, `store_refused`, ...) passes through unchanged with nothing left behind. The record carries `lead` (the caller) so the fork counts against that lead's subtree quota though it sits beside its source. The reply is `{id, role, tier}` plus `from:{agent, at}` and `copied` (the rows the fork carried over).

**Limits.** `set_limit {role?, max}` caps one role, or all agents in total; `max: null` clears. `get_count` counts the ACTIVE agents this registry spawned: one that exists and is not paused (ai_core `status` `paused`, read off its own store, so a restart keeps it; a `task_registry` holder status is not consulted, so this works without it). Pausing an agent, a `done` or `failed` `report` (it pauses the reporter) or `delete_agent` frees its slot; `resume` takes it back and is refused `limit` when the caps are full (`get_count {resume:id}` answers that for ai_core). An agent that will not answer `status` counts as active. `spawn limits:{total?, per_role?}` hands a sub-lead part of the caller's quota; a subtree never exceeds what it was given. Counts are read off the records (`spawned_by`, `role`), so a delete lowers them and a restart rebuilds them.

**No cleanup.** `report` only messages the parent (and pauses the reporter on `done`/`failed`): nothing is deleted. `delete_agent` is the only way out.
