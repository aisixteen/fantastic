# web — uvicorn HTTP host
Renders nothing of its own (an undeclared `/` is a 404): it serves `/<id>/file/<path>` (the `read_stream` file proxy) and the favicon (`/_assets/favicon.png`). Frontend html agents live in an app on the TS kernel. Verb-invocation surfaces are sub-agents (web_ws, web_rest): they DECLARE routes via the duck-typed `get_routes` verb (pure data — `{kind, method?, path}`) and hand the live endpoint for each path to this host through the duck-typed `route_endpoints(agent)` module hook. A leg declaring a route without that hook fails web boot. Two legs declaring the same literal route (same kind, method and path with no `{`) also fail web boot, and `mount` answers an error naming both; shared patterns such as `/{host_id}/ws` stay allowed. `port` field on the record is where it binds; `bind` is the address the listener binds, else `host`, else `127.0.0.1` (loopback); `host` is the address the guard judges by. Set `bind: 0.0.0.0` to publish (a container): the listener takes every address and the guard keeps its loopback identity, so `localhost:<port>` is admitted. EVERY request — GET/HEAD/OPTIONS, unsafe methods and the websocket upgrade — whose `Host` header is not this host's own authority (`<host>:<port>`, plus `localhost`/`127.0.0.1`/`[::1]` on that port when the bind is loopback) is refused — 403 / refused upgrade, logged; a `host` of `0.0.0.0` answers only `Host: 0.0.0.0:<port>`, so a LAN name or a tunnel name is refused, and a `bind` alone never changes the guard's answers (a DNS-rebinding page names its own domain in Host). Websocket upgrades and non-GET/HEAD/OPTIONS requests from a browser `Origin` that is not this host's own (`http://<host>:<port>`, both loopback spellings when loopback) nor listed in the record's `allowed_origins` (exact strings) are refused — 403 / refused upgrade, logged. No Origin header (CLI, curl, a bridge) passes; the leg's `ingress_rule` still gates it. Both fields are ordinary record meta: create_agent, a roster yaml, update_agent.
