# Test coverage of the closed issues

Purpose: every closed issue of `aisixteen/fantastic` maps to the tests that prove its behaviour on `main`, so a later change, rewrite or merge cannot silently undo it (issue #351). Last updated 2026-10-27 against `main` at `16d36778`, for the 123 closed issues numbered 45 to 432.

Update rule: when an issue closes, add or update its row in the same PR. A row names only tests that exist on `main`; never write a test name from memory.

## Status key

| status | meaning |
|---|---|
| covered | at least one named unit test and at least one e2e test |
| units only | unit tests named, no e2e on `main` yet |
| e2e only | an e2e test, no unit test |
| missing | neither found |
| deferred to the e2e phase | the e2e column: no e2e on `main` yet, one is owed in the e2e phase (#351 step 3) |

## How the table was built

The closing PRs come from GitHub's closing references, or, where there are none, from merged PRs that name the issue. For each PR the unit tests are the `#[test]` / `#[tokio::test]` functions and Python `test_` functions it added, kept only if the name still resolves in the file on `main`; the ones whose names share the most words with the issue come first, at most four per row. The e2e column lists the `e2e/tests/<group>/E<n>_<name>` folders the PR touched. An e2e folder is listed only when the PR changed a file in it other than its README, and a PR that touched more than four folders is not credited with any. A row that says `none found` was not matched by this method and needs a hand check. "Units only" on a row therefore means "no e2e folder was touched by the closing PR(s)".
